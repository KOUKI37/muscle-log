# muscle-log

筋トレの記録アプリ。iOS / Android に対応し、オフラインで動作する（サーバー・アカウント登録なし）。

個人開発。企画・設計・実装・デバッグを一人で担当した。

## 概要

muscle-log は、日々のトレーニング内容（種目・重量・レップ数）を記録するスマホアプリ。サーバーを持たず、記録はすべて端末内の SQLite に保存する。通信できない場所でも使える。

前回の記録をもとに、今日の分だけ調整して入力できるようにした。前回のメニューをワンタップで複製できる。種目ごとに前回の重量・レップ数を表示し、過去の履歴から次にやる種目の候補も出す。毎回ゼロから入力する手間を減らすのが狙い。

見た目は黒に近い背景と赤のアクセントカラーを基調にしている。ダークモードとライトモードがあり、設定画面で切り替えられる。選択は端末に保存され、次回起動時も引き継がれる。

---

## 解決した課題

既存の筋トレ記録アプリの多くは、毎回すべて手で入力する前提で作られている。実際のトレーニングは、同じ種目を似た重量・レップ数で繰り返すことが多く、入力が面倒だと記録が続かなくなる。

そこで、入力の手間を減らすことを最優先の課題にした。

- 前回と同じ内容なら、記録を選んで複製するだけで済むようにする（前回コピー）
- 種目を選ぶ手間を、過去の履歴から出す候補で減らす（次の種目の提案）
- 前回の重量・レップ数を見るために画面を行き来しなくて済むようにする（前回の記録の表示）

## 主な機能

### 1. トレーニング記録
種目を複数追加し、それぞれに複数のセット（重量・レップ数）を記録する。種目ごとにメモも残せる。日付は前日・翌日ボタンかカレンダーで選ぶ。記録の作成・編集・削除ができる。

- 重量とレップ数は、どちらか片方だけの入力でも保存できる。未入力の項目は画面上で「-」と表示する。
- 保存・更新の前に確認ダイアログを表示する。キャンセルすると入力内容を保ったまま画面に戻る。
- 編集画面では日付を変更できない。

### 2. 履歴の一覧・詳細
日付順の一覧から、各記録の種目・セット内容を確認できる。

### 3. 前回コピー
履歴の中から記録を選び、「この内容をコピーして今日の記録にする」を押すと、種目とセットを引き継いだ新しい入力画面が開く。日付は今日になり、内容は自由に編集できる。保存すると新しい記録として残り、元の記録は変更されない。

### 4. 次の種目の提案
種目を入力すると、過去の履歴から「その種目の直後によく記録されている種目」を集計して候補に出す。たとえば、いつもベンチプレスの次にインクラインプレスをしていれば、ベンチプレスの後にインクラインプレスが候補に出る。タップで種目を追加できる。履歴が少ない場合は、よく使う種目を候補にする。

### 5. 前回の重量・レップ数の表示
種目名を入力すると、その種目を最後に記録したときの重量・レップ数を表示する。ワンタップでそのままセットにコピーできる。

### 6. ダークモード / ライトモード切り替え
設定画面で「端末設定に従う / ライト / ダーク」を選べる。選択はアプリを再起動しても保持される。配色は共通の色定義にまとめてあり、全画面が一度に切り替わる。

## 使用技術

| 領域 | 技術 | 採用理由 |
|---|---|---|
| 言語 | TypeScript | 型チェックにより、DB スキーマからフォームの状態管理までの整合性を保つ |
| フレームワーク | React Native + Expo (SDK 57) | 1つのコードベースで iOS / Android に対応できる。Expo Go で実機の動作をすぐ確認できる |
| ルーティング | Expo Router | ファイルベースのルーティング。画面構成がディレクトリ構造に対応する |
| データベース | SQLite (`expo-sqlite`) | 端末内で完結し、オフラインで動く |
| ORM / マイグレーション | Drizzle ORM (`drizzle-orm` / `drizzle-kit`) | スキーマ定義から型と SQL マイグレーションを生成できる。自己結合のクエリも型付きで書ける |
| 日付選択 | `@react-native-community/datetimepicker` | iOS / Android の標準の日付選択 UI を使う。Web ではブラウザ標準の日付入力を使う |
| テーマ管理 | React Context + `@react-native-async-storage/async-storage` | ダーク/ライトの選択を一か所で管理し、端末に保存する。OS の設定（`useColorScheme`）にも従える |
| フォント | `expo-font` + Dela Gothic One（`@expo-google-fonts`） | 日本語に対応した極太フォント。見出しなど短い文言にだけ使い、本文には使わない |

サーバーを持たない構成にしたのは、個人の記録アプリにアカウント管理やバックエンドの運用は不要と判断したため。将来クラウド同期が必要になったら、ローカル DB を正として同期の仕組みを追加する。

## 使い方

### 必要なもの
- Node.js
- スマートフォン（[Expo Go](https://expo.dev/go) アプリをインストール）または Android エミュレータ
- Expo アカウント（Expo Go と `npx expo login` の両方で同じアカウントにサインインする）

### セットアップと起動

```bash
npm install
npm start
```

ターミナルに表示される QR コードを、iPhone は標準カメラアプリで、Android は Expo Go アプリで読み取るとアプリが起動する。

### その他のコマンド

| コマンド | 内容 |
|---|---|
| `npm run typecheck` | TypeScript の型チェック |
| `npm run android` | Android エミュレータで起動 |
| `npm run web` | Web ブラウザで起動 |
| `npx drizzle-kit generate` | `src/db/schema.ts` の変更から SQL マイグレーションを生成 |

├── _layout.tsx               共通ナビゲーション + 起動時マイグレーション + フォント読み込み

│   ├── Card.tsx                 共通カード
│   ├── TextField.tsx            共通テキスト入力
│   └── CenteredMessage.tsx     ローディング / 空状態の共通表示
├── utils/
│   ├── date.ts                 日付フォーマット・演算

│   └── alert.ts                確認ダイアログ（Web とネイティブの差を吸収）
└── theme/
    ├── colors.ts                ライト/ダーク配色の定義
    ├── fonts.ts                  見出し用フォントの定義

画面は DB を直接触らず、すべての読み書きを `src/db/queries.ts` の関数経由で行う。クエリの変更やスキーマ変更の影響を、このファイルに閉じ込められる。

### データモデル

```
workout        1回のトレーニング（日付のみ）
  └─ exercise_entry   その日の種目（種目名・表示順・メモ）
       └─ set_entry        1セットごとの記録（重量・レップ数。どちらも未入力を許可）
```

セットを独立した行として持つため、「3セット目だけ重量を落とした」といった記録をそのまま表せる。種目別の最大重量の推移のような集計にも対応しやすい。メモは種目ごとに持たせた。1日の総評より、「この種目はフォームを意識した」のような種目ごとのメモのほうが使いやすいため。

種目マスタは持たず、`exercise_entry.name` に種目名をそのまま保存している。次の種目の提案も前回値の表示も、この文字列の集計だけで実現できるので、マスタの管理は不要と判断した。

## 工夫した点

### 1. 「次の種目」の提案を、AI を使わず SQL の自己結合で実装した

過去の全履歴から、同じワークアウト内である種目の直後に来た種目を数え、多い順に提案する。`exercise_entry` テーブルを表示順（`sort_order`）で自己結合するクエリ1本で実装している。

```sql
-- 概念的なイメージ
SELECT next.name, COUNT(*) AS count
FROM exercise_entry AS current
JOIN exercise_entry AS next
  ON current.workout_id = next.workout_id
 AND next.sort_order = current.sort_order + 1
WHERE current.name = ?
GROUP BY next.name
ORDER BY count DESC
```

機械学習も検討したが、このアプリでは単純な頻度集計で十分に使える提案になり、実装も簡単で、なぜその候補が出るのかも説明しやすい。履歴が少ない場合や初めての種目では、よく使う種目を候補にする。

### 2. 入力の手間を減らす機能を、役割を分けて複数用意した

「前回コピー」は記録まるごとの複製で、「前回の重量・レップ数の表示」は種目単位の参照とコピー。前者は「今日もほぼ同じメニュー」の場合、後者は「今日は種目を選び直すが、重量は前回を参考にしたい」場合に使う。同じ入力フォームの上でどちらも使える。

種目名の入力中は、1文字ごとに DB へ問い合わせないよう 400ms 待ってから検索する。同じ種目名の検索結果は、フォーム内でキャッシュして再利用している。

### 3. タイムゾーンによる日付のずれを修正した

日付を1日進める・戻す操作で、進めても変わらない、戻すと2日戻る、という不具合が出た。原因は、`Date#toISOString()` が常に UTC に変換することだった。日本時間（UTC+9）では、変換のときに日付がずれる。`toISOString()` をやめ、`getFullYear()` / `getMonth()` / `getDate()` で日付文字列を組み立てるようにして、日付の処理全体をタイムゾーンに依存しない形にそろえた。

### 4. 保存後の画面遷移を直した

前回コピーで複製して保存したあと、`router.back()` で前の画面に戻していた。そのため、コピー元の古い記録の詳細画面に戻り、保存できたのか分かりにくかった。`createWorkoutWithDetails` が返す新しい記録の ID を使い、保存後は新しい記録の詳細画面へ直接移動するようにした。

### 5. 実機で使って見つかった不具合の修正

実際にアプリを使って見つかった問題を直した。

- 回数の入力欄が画面の右にはみ出していた。入力欄が縮まなかったのが原因で、`minWidth: 0` を指定して直した。
- Web 版では日付選択が開かなかった。日付選択のライブラリが Web では何も表示しないのが原因。Web ではブラウザ標準の日付入力を使うようにした。
- 重量とレップ数の両方を入力しないと保存できなかった。どちらか片方でも保存できるようにし、DB の列を未入力（null）を許す形に変更した。履歴の画面では、未入力を「NaN」や「null」ではなく「-」と表示する。

### 6. 開発環境で起きた問題への対応

- OneDrive の同期フォルダ内で開発していたため、`node_modules` のファイル操作と同期が競合し、`npm install` が `EPERM` で失敗した。`node_modules` の実体を OneDrive の外に置き、プロジェクト内にはディレクトリジャンクションを作って解決した。
- Expo Go が対応する SDK とプロジェクトの SDK が違うと、実機で開けない。SDK 54 から 57 に上げ、`npx expo install --fix` で依存パッケージを SDK 57 対応のバージョンにそろえた。あわせて、Expo Go で開くのに Expo アカウントへのサインインが必要になった点にも対応した。

### 7. 色の定義を一か所にまとめ、コントラスト比を計算して配色を調整した

配色は `ThemeColors` という型に、背景・文字・アクセントなどの色をまとめて定義し、ライト用とダーク用の2種類の値を用意した。画面側は色を直接指定せず、`useTheme()` でこの定義を参照する。そのため、ボタンやカードなどの共通コンポーネントを含め、アプリ全体が一度に切り替わる。選んだテーマは `AsyncStorage` に保存し、次回起動時に復元する。

文字が読みにくくならないよう、文字色と背景色のすべての組み合わせについて、WCAG のコントラスト比を計算するスクリプトを書いた。半透明の色は、背景と合成した色で計算した。基準に届かない組み合わせが4件あり、すべて修正した（例: ライトモードの主要ボタンの白文字が 4.19:1 で、基準の 4.5:1 に届いていなかった）。

見出し用に最初に選んだ Google Fonts の欧文フォント（Bebas Neue / Barlow）は日本語の字形を持たないことが、実装中に分かった。日本語に対応した Dela Gothic One に変更した。

アプリアイコンも黒背景と赤のアクセントでそろえた。Android のアダプティブアイコンは、端末によって円形や角丸四角で切り取られる。そのため、アイコンの図柄が切り取られない範囲に収まるよう縮小して配置し、円形の切り取りを再現して欠けがないことを確認してから書き出した。
