# muscle-log

筋トレの記録アプリです。iOS / Android で使えて、オフラインでも動きます（サーバーもアカウント登録もありません）。

個人で開発しました。考えるところから、設計、実装、バグ直しまで、すべて一人でやりました。

## 概要

muscle-log は、毎日のトレーニング（種目・重量・レップ数）を記録するスマホアプリです。サーバーは使わず、記録はすべてスマホの中の SQLite に保存します。電波がない場所でも使えます。

前回の記録をもとに、今日の分だけ直して入力できます。前回のメニューはワンタップでコピーできます。種目ごとに前回の重量とレップ数を表示し、過去の履歴から次にやりそうな種目も出します。毎回ゼロから入力する手間を減らすのがねらいです。

見た目は黒に近い背景と赤をメインにしています。ダークモードとライトモードがあり、設定画面で切り替えられます。選んだ内容はスマホに保存されるので、次に起動したときも同じです。

---

## 困っていたこと

今ある筋トレ記録アプリの多くは、毎回すべて手で入力する作りになっています。でも実際のトレーニングは、同じ種目を似た重量とレップ数で繰り返すことが多いです。入力が面倒だと、記録が続きません。

そこで、入力の手間を減らすことを一番の目標にしました。

- 前回と同じ内容なら、記録を選んでコピーするだけで済むようにする（前回コピー）
- 種目を選ぶ手間を、過去の履歴から出す候補で減らす（次の種目の提案）
- 前回の重量とレップ数を見るために、画面を行ったり来たりしなくて済むようにする（前回の記録の表示）

## 主な機能

### 1. トレーニング記録
種目をいくつでも追加でき、それぞれに複数のセット（重量・レップ数）を記録できます。種目ごとにメモも残せます。日付は前日・翌日ボタンかカレンダーで選びます。記録は作成・編集・削除ができます。

- 重量とレップ数は、片方だけ入力しても保存できます。入力していない項目は画面に「-」と表示します。
- 保存や更新の前に、確認ダイアログを表示します。キャンセルすると、入力した内容はそのままで画面に戻ります。
- 編集画面では日付を変えられません。

### 2. 履歴の一覧・詳細
日付順の一覧から、それぞれの記録の種目とセットの内容を見られます。

### 3. 前回コピー
履歴から記録を選んで「この内容をコピーして今日の記録にする」を押すと、種目とセットが入った新しい入力画面が開きます。日付は今日になり、内容は自由に直せます。保存すると新しい記録になり、コピー元の記録は変わりません。

### 4. 次の種目の提案
種目を入力すると、過去の履歴から「その種目のすぐあとによく記録されている種目」を数えて、候補として出します。たとえば、いつもベンチプレスの次にインクラインプレスをしていれば、ベンチプレスのあとにインクラインプレスが候補に出ます。タップすると種目を追加できます。履歴が少ないときは、よく使う種目を候補にします。

### 5. 前回の重量・レップ数の表示
種目名を入力すると、その種目を最後に記録したときの重量とレップ数を表示します。ワンタップでそのままセットにコピーできます。

### 6. ダークモード / ライトモードの切り替え
設定画面で「端末の設定に合わせる / ライト / ダーク」を選べます。選んだ内容は、アプリを再起動しても残ります。使う色は一つのファイルにまとめてあるので、すべての画面がいっぺんに切り替わります。

## 使った技術

| 項目 | 技術 | 選んだ理由 |
|---|---|---|
| 言語 | TypeScript | 型チェックのおかげで、DB のテーブルからフォームの入力値まで、間違いに気づきやすい |
| フレームワーク | React Native + Expo (SDK 57) | 1つのコードで iOS / Android の両方に対応できる。Expo Go ですぐ実機で試せる |
| 画面の切り替え | Expo Router | ファイルを置くだけで画面が作れる |
| データベース | SQLite (`expo-sqlite`) | スマホの中だけで動き、オフラインでも使える |
| ORM / マイグレーション | Drizzle ORM (`drizzle-orm` / `drizzle-kit`) | テーブルの書き方から、型と SQL マイグレーション（テーブルを変えるための SQL）を作れる。自己結合のクエリも型付きで書ける |
| 日付選択 | `@react-native-community/datetimepicker` | iOS / Android 標準の日付選択画面を使う。Web ではブラウザ標準の日付入力を使う |
| ダーク / ライトの設定 | React Context + `@react-native-async-storage/async-storage` | ダーク / ライトの選択を一か所で扱い、スマホに保存する。OS の設定（`useColorScheme`）にも合わせられる |
| フォント | `expo-font` + Dela Gothic One（`@expo-google-fonts`） | 日本語で使える極太フォント。見出しなどの短い文だけに使い、本文には使わない |

サーバーを使わない作りにしたのは、個人の記録アプリにアカウント管理やサーバーの運用は要らないと考えたからです。将来クラウドにも保存したくなったら、スマホの中のデータを元にして、クラウドと内容をそろえる仕組みを足す予定です。

## 使い方

### 必要なもの
- Node.js
- スマートフォン（[Expo Go](https://expo.dev/go) アプリを入れておく）または Android エミュレータ
- Expo アカウント（Expo Go と `npx expo login` の両方で、同じアカウントにサインインする）

### インストールと起動

```bash
npm install
npm start
```

ターミナルに出る QR コードを、iPhone は標準のカメラアプリで、Android は Expo Go アプリで読み取ると、アプリが起動します。

### そのほかのコマンド

| コマンド | 内容 |
|---|---|
| `npm run typecheck` | TypeScript の型チェック |
| `npm run android` | Android エミュレータで起動 |
| `npm run web` | Web ブラウザで起動 |
| `npx drizzle-kit generate` | `src/db/schema.ts` の変更をもとに SQL マイグレーションを作る |

画面は DB を直接さわらず、読み書きはすべて `src/db/queries.ts` の関数を通して行います。クエリやテーブルを変えたときに直す場所が、このファイルだけで済みます。

### データの持ち方

```
workout        1回のトレーニング（日付のみ）
  └─ exercise_entry   その日の種目（種目名・表示順・メモ）
       └─ set_entry        1セットごとの記録（重量・レップ数。どちらも未入力OK）
```

セットを1行ずつ別に持っているので、「3セット目だけ重量を落とした」という記録もそのまま残せます。種目ごとの最大重量の変化を調べるときにも、扱いやすいです。メモは種目ごとに持たせました。1日の感想より、「この種目はフォームを意識した」のように種目ごとに書けるほうが使いやすいからです。

種目だけを入れておくテーブルは作らず、`exercise_entry.name` に種目名をそのまま保存しています。次の種目の提案も、前回の値の表示も、この文字列を数えるだけでできるので、種目テーブルを管理する必要はないと考えました。

## 工夫した点

### 1. 「次の種目」の提案を、AI を使わず SQL の自己結合で作った

過去の履歴すべてから、同じワークアウトの中である種目のすぐあとに来た種目を数えて、多い順に出します。`exercise_entry` テーブルを表示順（`sort_order`）で自己結合する、1本のクエリでできています。

```sql
-- イメージ
SELECT next.name, COUNT(*) AS count
FROM exercise_entry AS current
JOIN exercise_entry AS next
  ON current.workout_id = next.workout_id
 AND next.sort_order = current.sort_order + 1
WHERE current.name = ?
GROUP BY next.name
ORDER BY count DESC
```

機械学習も考えましたが、このアプリでは単純に数えるだけで十分使える提案になります。作るのも簡単で、なぜその候補が出たのかも説明しやすいです。履歴が少ないときや、初めての種目のときは、よく使う種目を候補にします。

### 2. 入力の手間を減らす機能を、役割を分けて複数用意した

「前回コピー」は記録まるごとのコピーで、「前回の重量・レップ数の表示」は種目ごとに前回の値を見て、コピーする機能です。前者は「今日もほぼ同じメニュー」のとき、後者は「今日は種目を選び直すけれど、重量は前回を参考にしたい」ときに使います。同じ入力フォームの上で、どちらも使えます。

種目名を入力している間は、1文字ごとに DB で検索しないように、400ms 待ってから検索します。同じ種目名の検索結果は、フォームの中に覚えておいて、もう一度使います。

### 3. タイムゾーンで日付がずれる問題を直した

日付を1日進める・戻す操作で、進めても変わらない、戻すと2日戻る、という不具合が出ました。原因は、`Date#toISOString()` が必ず UTC に変換することでした。日本時間（UTC+9）だと、この変換で日付がずれます。`toISOString()` をやめて、`getFullYear()` / `getMonth()` / `getDate()` で日付の文字列を作るようにしました。これで、どのタイムゾーンでも日付がずれなくなりました。

### 4. 保存したあとの画面移動を直した

前回コピーで複製して保存したあと、`router.back()` で前の画面に戻していました。そのため、コピー元の古い記録の詳細画面に戻ってしまい、保存できたのか分かりにくくなっていました。`createWorkoutWithDetails` が返す新しい記録の ID を使って、保存後は新しい記録の詳細画面へ直接移動するようにしました。

### 5. 実機で使って見つかった不具合を直した

実際にアプリを使って見つかった問題を直しました。

- 回数の入力欄が、画面の右にはみ出していました。入力欄が縮まなかったのが原因で、`minWidth: 0` を指定して直しました。
- Web 版で日付選択が開きませんでした。日付選択のライブラリが、Web では何も表示しないのが原因です。Web ではブラウザ標準の日付入力を使うようにしました。
- 重量とレップ数の両方を入力しないと保存できませんでした。片方だけでも保存できるようにして、DB の列も未入力（null）を許す形に変えました。履歴の画面では、未入力を「NaN」や「null」ではなく「-」と表示します。

### 6. 開発中に起きた問題への対応

- OneDrive の同期フォルダで開発していたため、`node_modules` のファイル操作と同期がぶつかり、`npm install` が `EPERM` で失敗しました。`node_modules` の本体を OneDrive の外に置き、プロジェクト内にはそこへのリンク（ジャンクション）を作って解決しました。
- Expo Go が対応している SDK とプロジェクトの SDK が違うと、実機で開けません。SDK 54 から 57 に上げ、`npx expo install --fix` で、使っているパッケージを SDK 57 に合うバージョンにそろえました。あわせて、Expo Go で開くには Expo アカウントへのサインインが必要になった点にも対応しました。

### 7. 色を一か所にまとめ、コントラスト比を計算して色を調整した

背景・文字・アクセントなどの色を `ThemeColors` という型に入れて、ライト用とダーク用の2セットを用意しました。画面のコードでは色を直接書かず、`useTheme()` で今の色を受け取ります。そのため、ボタンやカードなどの共通部品も含めて、アプリ全体がいっぺんに切り替わります。選んだ設定は `AsyncStorage` に保存し、次に起動したときに読み込みます。

文字が読みにくくならないよう、文字色と背景色のすべての組み合わせについて、WCAG のコントラスト比を計算するスクリプトを書きました。半透明の色は、背景と重ねた色で計算しました。基準に届かない組み合わせが4つあり、すべて直しました（例：ライトモードのメインボタンの白文字が 4.19:1 で、基準の 4.5:1 に届いていませんでした）。

見出し用に最初に選んだ Google Fonts の欧文フォント（Bebas Neue / Barlow）は、日本語の文字が入っていないことが、作っている途中で分かりました。そこで、日本語に対応した Dela Gothic One に変えました。

アプリアイコンも、黒い背景と赤でそろえました。Android のアダプティブアイコンは、スマホによって円形や角丸四角に切り抜かれます。そのため、アイコンの絵が切り抜かれない範囲に収まるよう小さめに置きました。円形に切り抜いたときに欠けないことを確かめてから、書き出しました。
