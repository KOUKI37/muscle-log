# muscle-log

筋トレの記録アプリ。iOS / Android で使えて、オフラインでも動く（サーバーもアカウント登録もなし）。

個人開発。実装は AI のコーディングツール Claude Code を使って進めた（詳しくは[AI の使い方](#ai-の使い方)）。

## 概要

muscle-log は、毎日のトレーニング（種目・重量・レップ数）を記録するスマホアプリ。サーバーは使わず、記録はすべてスマホの中の SQLite に保存する。電波がない場所でも使える。

前回の記録をもとに、今日の分だけ直して入力できる。前回のメニューはワンタップでコピーできる。種目ごとに前回の重量とレップ数を表示し、過去の履歴から次にやりそうな種目も出す。毎回ゼロから入力する手間を減らすのが狙い。

見た目は黒に近い背景と赤をメインにしている。ダークモードとライトモードがあり、設定画面で切り替えられる。選んだ内容はスマホに保存されるので、次に起動したときも同じ。

## AI の使い方

このアプリのコードは、AI のコーディングツール Claude Code を使って書いた。自分でコードを一行ずつ書いたわけではない。

- 自分がやったこと：作りたいアプリの内容と、入力の手間を減らすという方針を決めた。オフラインでも使えるよう、SQLite でスマホの中に保存する案を出した。できた物を実機で使って、見つけた問題や要望を Claude Code に伝えた。「前回コピー」と「前回の重量・レップ数の表示」を役割で分ける案も、自分で決めた。
- Claude Code がやったこと：コードを書く。不具合の原因を調べて直す。使う技術（Expo、SQLite、Drizzle など）の選び方、データの持ち方、提案機能の作り方、配色の調整といった設計の判断も、ほとんど Claude Code が行った。

「工夫した点」の各項目には、誰が考えて誰が実装したかを書いてある。「使った技術」の表と「データの持ち方」も、Claude Code の判断によるもの。ただし、データの保存先に SQLite を使い、サーバーなしでオフラインでも動かすことは、自分の提案。

## 困っていたこと

今ある筋トレ記録アプリの多くは、毎回すべて手で入力する作りになっている。でも実際のトレーニングは、同じ種目を似た重量とレップ数で繰り返すことが多い。入力が面倒だと、記録が続かない。

そこで、入力の手間を減らすことを一番の目標にした。

- 前回と同じ内容なら、記録を選んでコピーするだけで済むようにする（前回コピー）
- 種目を選ぶ手間を、過去の履歴から出す候補で減らす（次の種目の提案）
- 前回の重量とレップ数を見るために、画面を行ったり来たりしなくて済むようにする（前回の記録の表示）

## 主な機能

### 1. トレーニング記録
種目をいくつでも追加でき、それぞれに複数のセット（重量・レップ数）を記録できる。種目ごとにメモも残せる。日付は前日・翌日ボタンかカレンダーで選ぶ。記録は作成・編集・削除ができる。

- 重量とレップ数は、片方だけ入力しても保存できる。入力していない項目は画面に「-」と表示する。
- 保存や更新の前に、確認ダイアログを表示する。キャンセルすると、入力した内容はそのままで画面に戻る。
- 編集画面では日付を変えられない。

### 2. 履歴の一覧・詳細
日付順の一覧から、それぞれの記録の種目とセットの内容を見られる。

### 3. 前回コピー
履歴から記録を選んで「この内容をコピーして今日の記録にする」を押すと、種目とセットが入った新しい入力画面が開く。日付は今日になり、内容は自由に直せる。保存すると新しい記録になり、コピー元の記録は変わらない。

### 4. 次の種目の提案
種目を入力すると、過去の履歴から「その種目のすぐあとによく記録されている種目」を数えて、候補として出す。たとえば、いつもベンチプレスの次にインクラインプレスをしていれば、ベンチプレスのあとにインクラインプレスが候補に出る。タップすると種目を追加できる。履歴が少ないときは、よく使う種目を候補にする。

### 5. 前回の重量・レップ数の表示
種目名を入力すると、その種目を最後に記録したときの重量とレップ数を表示する。ワンタップでそのままセットにコピーできる。

### 6. ダークモード / ライトモードの切り替え
設定画面で「端末の設定に合わせる / ライト / ダーク」を選べる。選んだ内容は、アプリを再起動しても残る。使う色は一つのファイルにまとめてあるので、すべての画面がいっぺんに切り替わる。

## 使った技術

| 項目 | 技術 | 選んだ理由 |
|---|---|---|
| 言語 | TypeScript | 型チェックのおかげで、DB のテーブルからフォームの入力値まで、間違いに気づきやすい |
| フレームワーク | React Native + Expo (SDK 57) | 1つのコードで iOS / Android の両方に対応できる。Expo Go ですぐ実機で試せる |
| 画面の切り替え | Expo Router | ファイルを置くだけで画面が作れる |
| データベース | SQLite (`expo-sqlite`) | スマホの中だけで動き、オフラインでも使える |
| ORM / マイグレーション | Drizzle ORM (`drizzle-orm` / `drizzle-kit`) | テーブルの書き方から、型と SQL マイグレーション（テーブルを変えるための SQL）を作れる。自己結合のクエリも型付きで書ける |
| 日付選択 | `@react-native-community/datetimepicker` | iOS / Android 標準の日付選択画面を使う。Web ではブラウザ標準の日付入力を使う |
| ダーク / ライトの設定 | React Context + `@react-native-async-storage/async-storage` | ダーク / ライトの選択を一か所で扱い、スマホに保存する。OS の設定（`useColorScheme`）にも合わせられる |
| フォント | `expo-font` + Dela Gothic One（`@expo-google-fonts`） | 日本語で使える極太フォント。見出しなどの短い文だけに使い、本文には使わない |

サーバーを使わない作りにしたのは、個人の記録アプリにアカウント管理やサーバーの運用は要らないと考えたから。将来クラウドにも保存したくなったら、スマホの中のデータを元にして、クラウドと内容をそろえる仕組みを足す予定。

## 使い方

### 必要なもの
- Node.js
- スマートフォン（[Expo Go](https://expo.dev/go) アプリを入れておく）または Android エミュレータ
- Expo アカウント（Expo Go と `npx expo login` の両方で、同じアカウントにサインインする）

### インストールと起動

```bash
npm install
npm start
```

ターミナルに出る QR コードを、iPhone は標準のカメラアプリで、Android は Expo Go アプリで読み取ると、アプリが起動する。

### そのほかのコマンド

| コマンド | 内容 |
|---|---|
| `npm run typecheck` | TypeScript の型チェック |
| `npm run android` | Android エミュレータで起動 |
| `npm run web` | Web ブラウザで起動 |
| `npx drizzle-kit generate` | `src/db/schema.ts` の変更をもとに SQL マイグレーションを作る |

### データの持ち方

```
workout        1回のトレーニング（日付のみ）
  └─ exercise_entry   その日の種目（種目名・表示順・メモ）
       └─ set_entry        1セットごとの記録（重量・レップ数。どちらも未入力OK）
```

セットを1行ずつ別に持っているので、「3セット目だけ重量を落とした」という記録もそのまま残せる。種目ごとの最大重量の変化を調べるときにも、扱いやすい。メモは種目ごとに持たせた。1日の感想より、「この種目はフォームを意識した」のように種目ごとに書けるほうが使いやすいから。

種目だけを入れておくテーブルは作らず、`exercise_entry.name` に種目名をそのまま保存している。次の種目の提案も、前回の値の表示も、この文字列を数えるだけでできるので、種目テーブルを管理する必要はないと考えた。

## 工夫した点

### 1. データベースに SQLite を使い、サーバーなしでオフラインでも動くようにした

（自分の提案。実装は Claude Code）

通っているジムに地下の店舗があり、既存の筋トレ記録アプリは、地下では電波が悪くて使えなかった。トレーニング中に記録できないと意味がないので、通信に頼らないアプリにしたいと考えた。そこで、データを保存する場所にスマホの中の SQLite を使い、サーバーを持たない作りにすることを自分から提案した。記録はすべてスマホの中に保存されるので、電波がない場所でも記録を入力して、前回の記録を見られる。

### 2. 「次の種目」の提案を、AI を使わず SQL の自己結合で作った

（Claude Code の判断。自分は提案機能がほしいと伝え、作り方は Claude Code が決めた）

過去の履歴すべてから、同じワークアウトの中である種目のすぐあとに来た種目を数えて、多い順に出す。`exercise_entry` テーブルを表示順（`sort_order`）で自己結合する、1本のクエリでできている。

```sql
-- イメージ
SELECT next.name, COUNT(*) AS count
FROM exercise_entry AS current
JOIN exercise_entry AS next
  ON current.workout_id = next.workout_id
 AND next.sort_order = current.sort_order + 1
WHERE current.name = ?
GROUP BY next.name
ORDER BY count DESC
```

機械学習も考えたが、このアプリでは単純に数えるだけで十分使える提案になる。作るのも簡単で、なぜその候補が出たのかも説明しやすい。履歴が少ないときや、初めての種目のときは、よく使う種目を候補にする。

### 3. 入力の手間を減らす機能を、役割を分けて複数用意した

（自分の判断。実装は Claude Code。400ms 待つ検索やキャッシュは、実装の中で Claude Code が入れた）

「前回コピー」は記録まるごとのコピーで、「前回の重量・レップ数の表示」は種目ごとに前回の値を見て、コピーする機能。前者は「今日もほぼ同じメニュー」のとき、後者は「今日は種目を選び直すけれど、重量は前回を参考にしたい」ときに使う。同じ入力フォームの上で、どちらも使える。

種目名を入力している間は、1文字ごとに DB で検索しないように、400ms 待ってから検索する。同じ種目名の検索結果は、フォームの中に覚えておいて、もう一度使う。

### 4. タイムゾーンで日付がずれる問題を直した

（日付がずれることを自分が見つけて Claude Code に伝えた。原因の調査と修正は Claude Code）

日付を1日進める・戻す操作で、進めても変わらない、戻すと2日戻る、という不具合が出た。原因は、`Date#toISOString()` が必ず UTC に変換することだった。日本時間（UTC+9）だと、この変換で日付がずれる。`toISOString()` をやめて、`getFullYear()` / `getMonth()` / `getDate()` で日付の文字列を作るようにした。これで、どのタイムゾーンでも日付がずれなくなった。

### 5. 保存したあとの画面移動を直した

（問題を自分が見つけて Claude Code に伝えた。原因の調査と修正は Claude Code）

前回コピーで複製して保存したあと、`router.back()` で前の画面に戻していた。そのため、コピー元の古い記録の詳細画面に戻ってしまい、保存できたのか分かりにくかった。`createWorkoutWithDetails` が返す新しい記録の ID を使って、保存後は新しい記録の詳細画面へ直接移動するようにした。

### 6. 実機で使って見つかった不具合を直した

（問題や要望を自分が Claude Code に伝えた。原因の調査と実装は Claude Code）

実際にアプリを使って見つかった問題を直した。

- 回数の入力欄が、画面の右にはみ出していた。入力欄が縮まなかったのが原因で、`minWidth: 0` を指定して直した。
- Web 版で日付選択が開かなかった。日付選択のライブラリが、Web では何も表示しないのが原因。Web ではブラウザ標準の日付入力を使うようにした。
- 重量とレップ数の両方を入力しないと保存できなかった。片方だけでも保存できるようにして、DB の列も未入力（null）を許す形に変えた。履歴の画面では、未入力を「NaN」や「null」ではなく「-」と表示する。

### 7. 開発中に起きた問題への対応

（Claude Code の判断と作業）

- OneDrive の同期フォルダで開発していたため、`node_modules` のファイル操作と同期がぶつかり、`npm install` が `EPERM` で失敗した。`node_modules` の本体を OneDrive の外に置き、プロジェクト内にはそこへのリンク（ジャンクション）を作って解決した。
- Expo Go が対応している SDK とプロジェクトの SDK が違うと、実機で開けない。SDK 54 から 57 に上げ、`npx expo install --fix` で、使っているパッケージを SDK 57 に合うバージョンにそろえた。あわせて、Expo Go で開くには Expo アカウントへのサインインが必要になった点にも対応した。

### 8. 色を一か所にまとめ、コントラスト比を計算して色を調整した

（Claude Code の判断と作業。コントラスト比の確認、フォントの変更、アイコンの調整も含む）

背景・文字・アクセントなどの色を `ThemeColors` という型に入れて、ライト用とダーク用の2セットを用意した。画面のコードでは色を直接書かず、`useTheme()` で今の色を受け取る。そのため、ボタンやカードなどの共通部品も含めて、アプリ全体がいっぺんに切り替わる。選んだ設定は `AsyncStorage` に保存し、次に起動したときに読み込む。

文字が読みにくくならないよう、文字色と背景色のすべての組み合わせについて、WCAG のコントラスト比を計算するスクリプトを書いた。半透明の色は、背景と重ねた色で計算した。基準に届かない組み合わせが4つあり、すべて直した（例：ライトモードのメインボタンの白文字が 4.19:1 で、基準の 4.5:1 に届いていなかった）。

見出し用に最初に選んだ Google Fonts の欧文フォント（Bebas Neue / Barlow）は、日本語の文字が入っていないことが、作っている途中で分かった。そこで、日本語に対応した Dela Gothic One に変えた。

アプリアイコンも、黒い背景と赤でそろえた。Android のアダプティブアイコンは、スマホによって円形や角丸四角に切り抜かれる。そのため、アイコンの絵が切り抜かれない範囲に収まるよう小さめに置いた。円形に切り抜いたときに欠けないことを確かめてから、書き出した。
